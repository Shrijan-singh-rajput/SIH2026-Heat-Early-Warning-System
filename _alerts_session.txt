## 8. Alert data model
- `Alert` interface with: id, severity (RiskLevel), title, area, affectedWards, description, trigger metrics, vulnerability metrics, recommendedAction, status (active/acknowledged/resolved), priority, intendedAudience, geographicScope, notificationChannels, issuedAt/acknowledgedAt/resolvedAt.
- `AlertCollection` interface with: metadata (scenario, assessmentPeriod, isDemo, source), alerts array.
- All five risk levels (LOW, MODERATE, HIGH, VERY HIGH, EXTREME) are present and independently testable.
- VERY HIGH and EXTREME are independently filterable and selectable.

## 9. Filtering/search functionality
- Risk level filter: ALL, LOW, MODERATE, HIGH, VERY HIGH, EXTREME (all five levels available, VERY HIGH and EXTREME independently selectable)
- Status filter: ALL, Active, Acknowledged, Resolved, Scheduled
- Priority filter: ALL, Low, Medium, High, Critical
- Search field: matches against alert ID, area, title, description
- Ward filter: matches against affected wards or area text
- All filter controls are keyboard-accessible native `<input>`/`<select>`/`<button>` elements with labels

## 10. Alert selection/detail functionality
- Clicking or keyboard-activating a table row selects it (toggle state)
- Selection indicated by 2px blue border + background + explicit "Selected" text label — never colour alone
- `aria-selected` attribute on rows
- Detailed alert panel shows: alert ID, severity RiskBadge, environmental conditions, thermal stress, vulnerability factors, and recommended heat actions
- Selected state exposes appropriate ARIA state
- Buttons have accessible names

## 11. Alert lifecycle implementation
